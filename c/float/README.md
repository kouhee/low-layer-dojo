# float/percent: 浮動小数点の振る舞い確認用サンプル

概要

このディレクトリには、同じ計算でもコンパイル環境（アーキテクチャ／最適化レベル／浮動小数点の設定）によって実行結果が変わり得ることを確認するための最小限の C サンプルが入っています。これは「なぜ結果が変わるか」を探すための教材・実験用コードであり、その理由自体はここでは記載していません。

ファイル

- `percent.c`  : 実験用の C ソース。double 型の計算結果を int に代入して表示します。
- `Makefile`   : x86_64, x86（-mfpmath 指定なし）、x86 (x87, `-mfpmath=387`) と ARM64 の各種最適化レベルでのコンパイル／実行を行うターゲットを用意しています。

使い方

前提:
- x86 用の `gcc` が利用可能であること（32bit 用に -m32 が効く環境）
- ARM64 のクロスコンパイラ `aarch64-linux-gnu-gcc` と `qemu-aarch64` がインストールされていること（ARM 実行をホスト上でエミュレートするため）

必要なツールのインストール（Debian / Ubuntu の例）:

以下は Debian/Ubuntu 系で必要なツールをインストールする例です。環境によってパッケージ名や利用可能性が異なる場合があります。root 権限（sudo）が必要です。

```sh
sudo apt-get update
sudo apt-get install -y \
  gcc-multilib \
  gcc-aarch64-linux-gnu \
  qemu-user qemu-user-static \
  make build-essential
```

- `gcc-multilib` は x86 で -m32 を使って 32bit バイナリを作るために必要です。
- `gcc-aarch64-linux-gnu` は ARM64 のクロスコンパイラです。
- `qemu-user` / `qemu-user-static` は ARM バイナリをエミュレートして実行するために使います。Makefile の `qemu-aarch64` 呼び出しが動作することを確認してください。

基本的な実行:

- 全ターゲットを順に実行して比較する:  
  make test

- 個別ターゲット例:
  - x86_64 (64bit):
    make x86_64-O0
    make x86_64-O2
    make x86_64-O3

  - x86 (32bit, `-mfpmath` 指定なし):
    make x86-O0
    make x86-O2
    make x86-O3

  - x87 (x86 32bit, x87 を使う `-mfpmath=387`):
    make x87-O0
    make x87-O2
    make x87-O3

  - ARM64 (クロスコンパイル + qemu):
    make arm-O0
    make arm-O2
    make arm-O3



何を観察するか

- 実行時の出力（`a = ...` と `b = ...`）を各ターゲット／最適化レベルで比較してください。値が異なるケースが観察できるはずです。
- コンパイラがどのような命令列を生成しているかを推測するために、最適化の違いがどのように影響するかを考察してください。
- 最適化オプションや浮動小数点関連のオプション（コンパイラフラグやターゲットの浮動小数点ユニットの違い）を変えて挙動がどう変わるか試してください。

調査のポイント（ヒント）

- 実行結果の違いが興味深い場合、デバッガや小さな修正を加えて追跡すると原因が見つけやすくなります。
- ここでは「なぜ環境で結果が変わるか」の直接的な解説は省いてあります。実験を通して理由を突き止めてください。
